# Правила разработки APEX DRIVE

## Контекст

APEX DRIVE — браузерная аркадная гонка для Windows PC. Текст проекта, игровые экраны, документация и комментарии пишутся на русском. Исходные имена API и идентификаторы в коде остаются на английском.

## Архитектура

- `frontend/src/core` связывает подсистемы, но не содержит их внутреннюю реализацию.
- Three.js отвечает только за представление; Rapier — за физическое состояние и столкновения.
- Физика обновляется фиксированным шагом 1/60 секунды через `PhysicsWorld`.
- Регистры машин и трасс являются источником игровых параметров. Не копировать цену и разблокировки в UI.
- Flask проверяет покупки и прогресс. Не принимать от клиента цену, награду или репутацию.
- Каждая система владеет созданными ею ресурсами и предоставляет очистку при выгрузке.
- Внешние модели не обязательны: для машины должен оставаться процедурный резервный вариант.

## Проверки

- После изменений интерфейса или игровой логики запускать `npm test` и `npm run build`.
- После изменений API или экономики запускать `pytest`.
- Описывать отдельно проверенное поведение и ещё не реализованные пункты.
- Не добавлять логотипы, марки машин и сторонние модели без проверки лицензии.

## Роли

Краткие задания профильных ролей находятся в `docs/agents/`. Это проектные описания для ручной передачи задачи агенту; они не создают фоновые или постоянные процессы.
