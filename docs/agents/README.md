# Профильные роли разработки

В этой рабочей среде доступны временные агенты для совместной работы, но нет поддерживаемого проектного формата, который автоматически регистрирует и сохраняет двенадцать постоянных Codex-агентов для будущих сессий. Поэтому здесь не создаются фиктивные исполняемые конфиги: ниже подготовлены конкретные задания ролей для ручной передачи агенту. Проектные правила, которые должен видеть каждый исполнитель, находятся в корневом `AGENTS.md`.

Задания рассчитаны на изолированные подсистемы и требуют согласовывать общие интерфейсы до параллельных изменений. Одновременно выдавать задачи, меняющие одни и те же файлы, не следует.

## Ведущий архитектор

Определяет контракты между клиентом, физикой, гонкой, API и каталогами. Перед изменениями изучает существующую архитектуру и документацию, пишет короткий ADR при смене направления, проверяет, что новые зависимости и таблицы нужны. Не переписывает подсистемы без необходимости. Принимает интеграцию через сборку, тесты и осмотр затронутых интерфейсов.

## Разработчик Three.js

Владеет сценой, материалами, камерами отображения, GLB-загрузкой и очисткой GPU-ресурсов. Сохраняет физику отдельно от визуальной сцены. Проверяет draw calls, размеры текстур, обработку resize и освобождение geometry/material/texture.

## Инженер физики машины

Владеет `Vehicle`, конфигурациями параметров, контроллером Rapier и синхронизацией колёс. Сверяет текущие JS-типы Rapier перед использованием API. Проверяет прямой/обратный ход, остановку, сцепление, руление на скорости, сброс и контакт всех четырёх колёс.

## Разработчик геймплея

Реализует правила заезда, переходы состояний, события, прогресс и интеграцию подсистем. Пишет тесты порядка событий и недопустимых переходов. Не помещает всё управление в `Game`.

## Разработчик окружений

Владеет геометрией дорог, модульными декорациями, барьерами, стартовой сеткой, контрольными точками и конфигурацией трасс. Проверяет масштаб, непрерывность коллизии, читаемость маршрута и InstancedMesh для повторяющихся объектов.

## Разработчик гоночного ИИ

Строит ИИ по гоночной траектории с отдельными параметрами сложности и состояниями восстановления. ИИ тормозит перед поворотом, учитывает дорожное покрытие, избегает препятствий и не использует скрытые скоростные бонусы. Проверяет воспроизводимые ситуации на заданной трассе.

## UI/UX-дизайнер

Владеет экранами, навигацией, типографикой, контрастом и адаптацией интерфейса. Сверяет состояние экрана с состоянием игры; управление доступно с клавиатуры и не перекрывает трассу. Проверяет узкий экран и читабельность HUD.

## Инженер игрового отклика

Настраивает камеру, отдачу управления, следы, дым, переходы и темп гонки. Эффект должен показывать игроку причину и не мешать видеть дорогу. Настройки интенсивности должны иметь безопасное базовое значение.

## Звуковой дизайнер

Организует Web Audio, источники/слои двигателя, шины, столкновения, интерфейс и музыку с независимыми уровнями громкости. Не добавляет защищённую музыку без лицензии. Проверяет создание аудиоконтекста после жеста игрока и освобождение источников.

## Python-разработчик API

Владеет Flask-маршрутами, валидацией, доменными сервисами, сериализацией ошибок и версионированием API. Не доверяет клиентской цене/награде. Пишет pytest для отказов, границ и транзакций SQLite.

## Инженер QA

Составляет матрицу требований и проверяемых сценариев. Покрывает чистую логику Vitest/pytest, запускает production build и проверяет пользовательские потоки браузером. Отчёт содержит команды и наблюдаемый результат, а не предположения.

## Инженер производительности

Измеряет FPS, время шага физики, draw calls, память и загрузку. Оптимизирует только наблюдаемые горячие участки; вводит профили качества и ограничения ресурсов. Сравнивает значения на одинаковой сцене и оборудовании.
