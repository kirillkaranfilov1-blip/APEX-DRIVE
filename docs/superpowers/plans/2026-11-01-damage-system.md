# Система повреждений машины — план реализации

> **Для исполнителей:** выполнять задачи последовательно; каждая задача заканчивается тестом, который проверяет её интерфейс.

**Цель:** при сильном ударе о преграду снижать состояние машины, показывать процедурную вмятину и обновлять шкалу HUD; рестарт восстанавливает машину.

**Архитектура:** `PhysicsWorld` будет собирать контактные события Rapier на фиксированных шагах и отдавать безопасные JS-данные подписчикам. `VehicleDamage` отделит расчёт состояния/зоны/задержки от `VehicleDamageVisual`, который локально деформирует визуальный кузов; физический коллайдер останется прежним. `Game` соединит событие с машиной и HUD.

**Технологии:** JavaScript ES Modules, Rapier 3D 0.19.3, Three.js 0.187.0, Vitest.

**Спецификация:** [docs/DAMAGE_SYSTEM_DESIGN.md](../../DAMAGE_SYSTEM_DESIGN.md)

## Глобальные ограничения

- Использовать Rapier для физики и коллизий; физика работает с фиксированным шагом 1/60 секунды.
- Повреждать только при ощутимом ударе; длительное трение о барьер не должно быстро обнулять состояние.
- Визуальные деформации не меняют физический коллайдер.
- Состояние ограничено 0–100 и восстанавливается при рестарте/новом заезде.
- Не добавлять тяжёлые эффекты и новые зависимости.

## Области повышенного внимания

- **Порог удара:** слабый контакт не меняет состояние — проверка модели и реального Rapier contact-force event.
- **Непрерывный контакт:** трение одним контактом не должно снимать здоровье каждый шаг — тест задержки урона.
- **Ориентация:** сила переводится в локальные координаты кузова, чтобы повреждалась ожидаемая сторона — тест направлений.
- **Повторное использование геометрии:** вмятина изменяет только геометрию конкретной машины и сбрасывается исходными вершинами — тест восстановления.
- **Сброс/финиш:** рестарт восстанавливает HUD и кузов; финиш сам по себе не ремонтирует машину — ручная браузерная проверка.
